## Дашборд

### Таблиця активності порожня, хоча передачі є

Найчастіше — дашборду немає що читати. Він бере дані з файлів
`/var/log/mmdvm/MMDVM-YYYY-MM-DD.log`, а сервіс може писати лише в journal.
Перевірте:

```bash
ls -la /var/log/mmdvm/MMDVM-$(date +%F).log
```

Якщо файлу немає — потрібен міст `journal2log`, див.
[INSTALL.md, розділ 5](INSTALL.md).

### Порожньо при фільтрі за окремим режимом

Було в старих версіях: буфер активності тримав лише 20 записів, тому при
інтенсивному трафіку в одному режимі (кілька сотень DMR-передач поспіль) усі
записи інших режимів витіснялися. Виправлено — буфер 1000 записів, фільтрація
на сервері. Перевірити склад буфера:

```bash
curl -s "http://localhost:85/api/activity?mode=YSF&limit=5" | python3 -m json.tool
```

### Час у логах не збігається

MMDVMHost пише логи **місцевим часом**, а не UTC. При виборі файлу логу треба
`datetime.now()`, а не `datetime.utcnow()` — інакше після півночі за UTC
дашборд шукає неіснуючий файл. У PHP-дашборді відповідно `time() + 10800`
для EEST (UTC+3).

### Помилки після ручного редагування dashboard.py

Перед перезапуском завжди перевіряйте синтаксис:

```bash
python3 -c "import ast; ast.parse(open('/opt/dashboard/dashboard.py', encoding='utf-8').read()); print('OK')"
```

Дві окремі структури `SERVICES` — у Python (для API і конфігів) і в JS (для
рендерингу UI). При зміні списку сервісів оновлюйте **обидві**.

## DMR

### BrandMeister відхиляє підключення: «has wrong configuration»

Логін і пароль правильні, але в Device Logs BM видно відмову.

**Причина:** у секції `[Info]` конфігу DMRGateway відсутній `Duplex=0`. Без
нього шлюз повідомляє майстру, що працює в дуплексі (`Slots=3` замість
`Slots=4`/DMO), і Script Engine BM відкидає симплексний хотспот.

```ini
[Info]
Duplex=0
```

**Як діагностували:** порівняння RPTC-пакетів у `tcpdump` — байт-дамп нашого
пакета проти пакета робочої системи одразу показав різницю в полі `Slots`.
Це виявилось значно швидше за перебирання паролів і конфігів:

```bash
sudo tcpdump -i any -X -n port 62031 or port 55555
```

### MMDVMHost не логіниться до майстра напряму

Так і має бути. Сучасний MMDVMHost шле `DMRP`, а не логін `RPTL` — між ним
і майстром обов'язково потрібен **DMRGateway**. Див. README, розділ
«Архітектура».

### Трафік іде не в ту мережу

При кількох `[DMR Network]` порядок має значення: мережа з **конкретними**
`TGRewrite` має стояти **першою**, а мережа з `PassAllTG` — після неї.
Інакше PassAll перехопить усе.

## D-Star

### Лінк до рефлектора відпадає і не відновлюється

Симптом: у логах `poll inactivity`, лінк розірвано, автоматичного релінку
не відбувається (спостерігали залипання до півтори доби).

Швидке лікування:

```bash
sudo systemctl restart ircddbgateway
```

Профілактика — автоматичний лінк при старті в `/etc/ircddbgateway`:

```ini
atStartup1=1
reflector1=XLX257 A
```

Якщо відпадання регулярні, поставте cron-вартового, який перевіряє стан лінка
і перелінковує (за аналогією з `Revert=1` у YSFGateway).

## YSF

### Після роботи в іншій кімнаті шлюз не повертається на домашню

У `YSFGateway.ini`:

```ini
Revert=1
```

### PHP MMDVM Dashboard не показує YSF-лінк

Дашборд пише поточний лінк у `/tmp/ysf_linked.txt` (з MQTT-топіка
`ysf-gateway/json`), звідки його читає PHP-панель. Перевірка:

```bash
cat /tmp/ysf_linked.txt
```

## Живлення та залізо

### Undervoltage detected

Найпоширеніша прихована причина зависань, збоїв SD і дивної поведінки модему.

```bash
vcgencmd get_throttled
journalctl -k --since "7 days ago" | grep -c "Undervoltage"
```

Розшифровка `get_throttled`:

| Значення | Що означає |
|---|---|
| `0x0` | все гаразд |
| `0x50000` | просідання напруги було раніше (біти «сталося») |
| `0x50005` | просідання **прямо зараз** |

**Лікування:** короткий товстий USB-кабель і блок живлення щонайменше
5 В / 2.5 А. Довгий тонкий кабель — найчастіший винуватець, навіть із хорошим
БЖ. Тисяча подій за тиждень — це не «дрібниця», а привід замінити кабель.

## Мережа

### Pi не повертається у Wi-Fi після перезавантаження роутера

NetworkManager припиняє спроби після кількох невдач, поки роутер ще
завантажується. Виправлення:

```bash
sudo nmcli connection modify "<назва-мережі>" connection.autoconnect-retries 0
```

`0` означає «пробувати нескінченно». Додатково допомагає невелика затримка
старту мережевих сервісів (10–15 с), щоб Pi не стартував раніше за роутер.

## Загальна гігієна системи

### Осиротілі процеси journalctl

Після експериментів із логами можуть лишатися підвислі `journalctl -f`, які
тримають CPU і файлові дескриптори тижнями:

```bash
ps aux | grep "journalctl -f" | grep -v grep
```

### Зайві сервіси

Перевірте, чи не працює у вас щось непотрібне — наприклад `monit` без правил
(тримає порт 2812) або мости під залізо, якого немає:

```bash
systemctl list-units --type=service --state=running
```

### Пам'ять дашборду

~76 МБ RSS одразу після старту — це нормально, базова вартість Python-бібліотек,
а не витік. Усі глобальні кеші обмежені за розміром, файлові дескриптори
закриваються. Якщо zram-swap заповнився після важкої операції (бекап), його
можна чисто скинути:

```bash
sudo swapoff -a && sudo swapon -a
```

## Перед тим як робити висновок про баг

Термінал через SSH інколи «склеює» рядки або губить символи — те, що виглядає
як помилка в коді, може бути артефактом відображення. Перевіряйте сирий вміст:

```bash
cat -A файл | head -20
```
